Easy Questions (Q1–60)

Core knowledge, single-service recall, foundational concepts

Q1
Easy
Domain 1: Organizational Complexity

A company wants to apply a policy that prevents any IAM user in member accounts from disabling AWS CloudTrail. Which AWS service feature should the Solutions Architect use?

  • A) Service Control Policies (SCPs) in AWS Organizations
  • B) IAM Permission Boundaries on each user
  • C) AWS Config rules with auto-remediation
  • D) AWS CloudTrail log file integrity validation

Correct: A

Why A: SCPs in Organizations apply to all accounts in the OU/Organization. A Deny SCP on cloudtrail:StopLogging applies organization-wide and cannot be overridden by local IAM policies.

Why B is wrong: Permission Boundaries must be applied per user — not scalable across hundreds of accounts.

Why C is wrong: Config rules detect violations but don't prevent them in real-time.

Why D is wrong: Log integrity validation detects tampering after the fact — it doesn't prevent disabling.

Q2
Easy
Domain 2: New Solutions — Networking

A company's Lambda function in a private subnet needs to access Amazon S3 without traffic traversing the internet. What is the MOST cost-effective solution?

  • A) Deploy a NAT Gateway in the public subnet
  • B) Create a Gateway VPC Endpoint for S3
  • C) Create an Interface VPC Endpoint for S3
  • D) Configure a VPN connection to S3

Correct: B

Why B: Gateway VPC Endpoints for S3 and DynamoDB are FREE — no hourly charge and no per-GB charge. Traffic stays in the AWS network.

Why A is wrong: NAT Gateway costs $0.045/hour + $0.045/GB. Very expensive for S3 traffic.

Why C is wrong: Interface Endpoint for S3 exists but has an hourly cost ($0.01/hour per AZ). Gateway Endpoint is free.

Why D is wrong: VPN to S3 doesn't make architectural sense — S3 is not on-prem.

Easy
Domain 2: New Solutions — Storage

A solutions architect needs to choose an S3 storage class for data that is accessed unpredictably — sometimes daily, sometimes not for months. The company wants to minimize cost without managing lifecycle policies manually. Which storage class should be used?

  • A) S3 Standard
  • B) S3 Intelligent-Tiering
  • C) S3 One Zone-IA
  • D) S3 Glacier Instant Retrieval

Correct: B

Why B: S3 Intelligent-Tiering automatically moves objects between access tiers (Frequent, Infrequent, Archive Instant) based on access patterns. No retrieval fees. Perfect for unknown/unpredictable access.

Why A is wrong: Standard doesn't automatically tier down — more expensive for rarely-accessed data.

Why C is wrong: One Zone-IA is for infrequently accessed but predictably so, with known lower resilience.

Why D is wrong: Glacier Instant Retrieval is for data accessed once a quarter or less.

Q4
Easy
Domain 2: New Solutions — Databases

A company needs a managed relational database with automatic failover across Availability Zones. If the primary instance fails, the database should automatically recover with minimal downtime. Which solution provides this?

  • A) RDS with Read Replicas in another AZ
  • B) RDS with Multi-AZ deployment
  • C) RDS with automatic backups enabled
  • D) RDS with manual snapshot replication to another AZ

Correct: B

Why B: RDS Multi-AZ maintains a synchronous standby replica in a different AZ. Failover is automatic (~60-120 seconds) via DNS endpoint switch.

Why A is wrong: Read Replicas use ASYNC replication and do NOT automatically failover. Manual promotion is required.

Why C is wrong: Backups help with point-in-time recovery but don't provide automatic failover.

Why D is wrong: Manual snapshots require manual restore — no automatic failover.

Q5
Easy
Domain 4: Migration

A company wants to migrate an Oracle database to Amazon Aurora PostgreSQL. The schema needs to be converted. Which combination of AWS services should be used?

  • A) AWS MGN and AWS DataSync
  • B) AWS Schema Conversion Tool (SCT) and AWS Database Migration Service (DMS)
  • C) AWS DMS only — it handles both schema and data migration
  • D) AWS Snowball and DMS

Correct: B

Why B: For heterogeneous migrations (different DB engines), SCT converts the schema/stored procedures first. DMS then migrates the data (Full Load + CDC for minimal downtime).

Why C is wrong: DMS only migrates data — it does NOT convert schemas between different database engines.

Why A is wrong: MGN is for server migrations (EC2), not database schema/data migration.

Why D is wrong: Snowball is for large-scale data transfer to S3, not database migration to Aurora.

Domain 2: Security

A company wants to detect unauthorized API calls and potentially malicious activity in their AWS account by analyzing VPC Flow Logs, CloudTrail logs, and DNS logs. Which AWS service should they enable?

  • A) AWS Macie
  • B) AWS Inspector
  • C) Amazon GuardDuty
  • D) AWS Security Hub

Correct: C

Why A is wrong: Macie finds sensitive data (PII) in S3 — it doesn't analyze VPC Flow Logs or CloudTrail for threats.

Why B is wrong: Inspector assesses EC2/ECR for vulnerabilities (CVEs) — it doesn't detect real-time threats.

Why D is wrong: Security Hub aggregates findings from GuardDuty and other services — but doesn't detect threats itself.

Q7
Easy
Domain 2: Compute

A company is running a web application on a fleet of EC2 instances behind an Application Load Balancer. They want the number of instances to automatically increase when CPU utilization exceeds 70%. Which Auto Scaling policy type should they use?

  • A) Scheduled Scaling
  • B) Step Scaling
  • C) Target Tracking Scaling
  • D) Simple Scaling

Correct: C

Why C: Target Tracking Scaling automatically adjusts capacity to maintain a specified metric at a target value (e.g., CPU at 70%). AWS manages scaling up and down automatically.

Why A is wrong: Scheduled Scaling adjusts at fixed times — not based on real-time CPU metrics.

Why B is wrong: Step Scaling requires manual definition of step adjustments — more complex configuration. Target Tracking is simpler and recommended by AWS for metric-based scaling.

Why D is wrong: Simple Scaling is the oldest type — it adds/removes one fixed amount and has a cooldown period. Target Tracking is more responsive.

Q9
Easy
Domain 2: Networking

A company has 20 VPCs across different AWS accounts and needs them to communicate with each other. New VPCs are being added monthly. Which solution provides the MOST scalable hub-and-spoke connectivity model?

  • A) VPC Peering connections between all VPCs
  • B) AWS Transit Gateway
  • C) AWS PrivateLink
  • D) AWS Direct Connect with a VGW in each VPC

Correct: B

Why B: Transit Gateway acts as a central hub. Each VPC connects once to TGW — no direct peering between VPCs needed. Adding a new VPC requires only one TGW attachment. Supports transitive routing.

Why A is wrong: VPC Peering is non-transitive. 20 VPCs need (20×19/2)=190 peering connections — not scalable. Requires route table updates for each pairing.

Why C is wrong: PrivateLink exposes specific services, not general VPC-to-VPC connectivity.

Why D is wrong: Direct Connect is for on-prem to AWS — not VPC-to-VPC connectivity.

Q10
Easy
Domain 2: Compute

An application has spiky, unpredictable traffic. Sometimes it processes 1,000 requests/minute, other times 0. The company wants the LOWEST cost with NO idle capacity charges. Which compute option is best?

  • A) EC2 Reserved Instances
  • B) EC2 On-Demand with Auto Scaling
  • C) AWS Lambda
  • D) Amazon ECS with Fargate (always-on)

Correct: C

Why C: Lambda charges only for compute time during invocations (milliseconds). Zero cost when idle. Perfect for spiky/unpredictable workloads. 1M free requests/month.

Why A is wrong: Reserved Instances pay 24/7 regardless of traffic — wasteful for variable workloads.

Why B is wrong: Auto Scaling reduces waste but minimum capacity still runs 24/7. Lambda is cheaper for spiky patterns.

Why D is wrong: Fargate always-on charges for CPU/memory at all times — not ideal when traffic can be 0.

Q61
Medium
Domain 1: Organizational Complexity

A company has a multi-account AWS Organizations structure. The security team wants to ensure CloudTrail is enabled in all accounts and cannot be disabled. They also want all CloudTrail logs centralized in a dedicated Log Archive account. What is the MOST efficient approach?

  • A) Enable CloudTrail in each account manually and ship logs via Kinesis Firehose to the Log Archive account
  • B) Create an Organization Trail from the management account, with log delivery to an S3 bucket in the Log Archive account. Apply an SCP that denies cloudtrail:DeleteTrail and cloudtrail:StopLogging to all member accounts
  • C) Use AWS Control Tower to manage CloudTrail independently per account
  • D) Use AWS Config to enable CloudTrail with auto-remediation in each account

Correct: B

Why B: Organization Trail automatically logs all accounts — no per-account setup. Logs go to centralized S3. SCP prevents anyone from stopping logging. This is the AWS recommended multi-account logging pattern.

Why A is wrong: Per-account CloudTrail configuration doesn't prevent admins from disabling it in their own accounts.

Why C is wrong: Control Tower does set up CloudTrail, but the question asks for enforcement via prevention — SCPs are the mechanism.

Why D is wrong: Config auto-remediation re-enables CloudTrail after it's been disabled — there's a window of non-compliance. SCP prevents disable in the first place.

Q62
Medium
Domain 2: New Solutions — DR

A financial services company has an RTO of 15 minutes and an RPO of 1 minute for their core banking application hosted in us-east-1. They need a DR strategy to eu-west-1. What should the architect recommend? (Select TWO)

  • A) Deploy Aurora Global Database with the primary in us-east-1 and a read replica cluster in eu-west-1
  • B) Enable daily RDS snapshots with cross-region copy to eu-west-1
  • C) Maintain a warm standby of ECS Fargate tasks at 25% capacity in eu-west-1, configured with Route 53 Failover routing
  • D) Use Backup & Restore with AMIs copied to eu-west-1
  • E) Deploy DynamoDB with a Read Replica in eu-west-1

Correct: A and C

Why A: Aurora Global has ~<1 sec replication lag (RPO <1 min satisfied). Can be promoted in <1 minute (contributes to RTO).

Why C: Warm Standby with 25% capacity + Route 53 Failover routing meets 15-minute RTO: DNS failover ~1 min + scale up to 100% ~10 min = ~11 min RTO.

Why B is wrong: Daily snapshots = up to 24 hours RPO — far exceeds the 1-minute requirement.

Why D is wrong: Backup & Restore has hours RTO — doesn't meet 15-minute requirement.

Why E is wrong: DynamoDB doesn't have "Read Replicas" — it has Global Tables (multi-active). Also, the question context implies a relational banking application using Aurora.

A company stores sensitive customer PII in multiple S3 buckets across the organization. The CISO wants automated discovery of PII and notification when new PII is found in any bucket. Which solution should the architect implement?

  • A) Enable GuardDuty and configure an EventBridge rule to trigger when S3 data events are detected

Why A is wrong: GuardDuty detects security threats, not PII content in objects.

Why C is wrong: Custom Lambda + Comprehend would work technically but is NOT the "least operational overhead" answer — Macie is the managed solution.

Why D is wrong: Inspector scans for CVEs in EC2/ECR — it doesn't scan S3 object content for PII.

A company runs 500 EC2 instances across 20 accounts. The infrastructure team suspects many instances are oversized. They want automated, ML-based right-sizing recommendations with minimal operational overhead. What should they implement?

  • A) Enable AWS Compute Optimizer at the organization level and review recommendations per service (EC2, ASG, Lambda, EBS)

Q65
Medium
Domain 2: Application Integration

An e-commerce platform needs to process orders reliably. Each order must be processed EXACTLY ONCE in the order received, with no duplicates. Orders are sent from multiple microservices. Which solution meets these requirements?

  • A) Amazon SQS Standard Queue with Lambda as consumer
  • B) Amazon SQS FIFO Queue with content-based deduplication enabled
  • C) Amazon SNS with Lambda subscribers
  • D) Amazon Kinesis Data Streams with Lambda

Correct: B

Why B: SQS FIFO provides: (1) exactly-once processing via deduplication ID; (2) strict message ordering (FIFO). Content-based deduplication uses SHA-256 hash of body to detect and discard duplicates.

Why A is wrong: SQS Standard is at-least-once delivery with best-effort ordering — duplicates possible, order not guaranteed.

Why C is wrong: SNS is a pub/sub push system — it doesn't guarantee ordering or exactly-once delivery.

Why D is wrong: Kinesis provides ordering within a shard but not exactly-once — duplicate processing possible with Lambda retries.

Medium
Domain 2: Networking

A company has a Direct Connect connection to AWS. They want to provide a backup connectivity path in case Direct Connect fails. They need the backup to be encrypted. What should the architect configure?

  • A) A second Direct Connect connection from a different provider
  • B) An AWS Site-to-Site VPN as a failover for Direct Connect, configured on the same Virtual Private Gateway
  • C) S3 Transfer Acceleration as a backup data path
  • D) A public Direct Connect VIF with encryption enabled

Correct: B

Why B: Site-to-Site VPN over internet provides encrypted backup. Using the same VGW means BGP routing prefers Direct Connect when available and automatically fails over to VPN. IPSec encryption satisfies the encryption requirement (Direct Connect itself is not encrypted by default).

Why A is wrong: A second Direct Connect is more expensive and takes weeks to provision — not ideal as a quick backup. Also, Direct Connect isn't encrypted natively.

Why C is wrong: S3 Transfer Acceleration is for S3 upload acceleration, not general network connectivity backup.

Why D is wrong: Public VIF carries public AWS service traffic — it doesn't replace private connectivity to your VPC.

Q68
Medium
Domain 2: Databases

A social media application has a read-heavy workload (95% reads, 5% writes). The DynamoDB table handles 100,000 reads per second at peak. Response time must be under 1 millisecond for user profile lookups. What should the architect add?

  • A) DynamoDB Global Secondary Index (GSI)
  • B) Amazon DynamoDB Accelerator (DAX)
  • C) Amazon ElastiCache for Memcached
  • D) DynamoDB Streams with Lambda pre-caching

Why C is wrong: ElastiCache Memcached can cache data but requires application-level cache management code changes. DAX is transparent (same API).

Why D is wrong: DynamoDB Streams + Lambda pre-caching is a complex custom solution — DAX is purpose-built and managed.

Q69
Medium
Domain 4: Migration

A company wants to migrate 200 TB of data from on-premises NAS storage to Amazon S3. The data center has a 10 Gbps internet connection shared with production traffic. The migration needs to complete within 2 weeks. Which approach should the architect recommend?

  • A) AWS DataSync over the existing internet connection
  • B) AWS Snowball Edge Storage Optimized devices
  • C) AWS Storage Gateway — Volume Gateway
  • D) S3 multipart upload with AWS CLI

Correct: B

Why B: 200 TB over internet: at 10 Gbps (1.25 GB/s), theoretical minimum = 200,000 GB / 1.25 = 160,000 seconds ≈ 44 hours. But the connection is SHARED — actual available bandwidth is much less. Plus DataSync overhead. Snowball Edge (80 TB usable each) = 3 devices. Shipped to AWS, ingested in days. No impact on production network.

Why A is wrong: With shared 10 Gbps, effective DataSync throughput might be 2-3 Gbps. 200 TB would take 200+ hours just for transfer + shared impact on production.

Why C is wrong: Storage Gateway Volume is for ongoing hybrid integration — not a bulk migration tool.

Why D is wrong: AWS CLI multipart upload has the same bandwidth constraint as option A — same network limitation applies.

A company uses Microsoft Active Directory on-premises. Employees need to access the AWS Management Console in multiple AWS accounts without separate IAM users. The company wants to use their existing AD credentials. Which solution provides this with the LEAST operational overhead?

  • A) Configure SAML 2.0 federation with individual IAM Identity Providers in each AWS account

Hard Questions (Q151–240)

Complex multi-constraint scenarios, architectural trade-off analysis, advanced service interactions

Q151
Hard
Domain 1: Organizational Complexity

A company has a multi-account AWS structure with a Management account, 3 OUs (Security, Production, Development), and 40 member accounts. A new regulatory requirement mandates that ALL S3 buckets must enforce server-side encryption with KMS keys managed by the Security OU's centralized KMS account. The policy must be enforced even if account admins try to disable it. What combination achieves this with the LEAST complexity? (Select TWO)

  • A) Apply an SCP to the Production and Development OUs that denies s3:PutObject unless the request header includes SSE-KMS encryption with specific KMS key ARNs from the Security account
  • B) Create CloudWatch Events rules in each account to detect non-encrypted uploads and trigger Lambda to delete the object
  • C) Enable S3 default encryption on all buckets using bucket policies that require SSE-KMS and reference the centralized KMS key ARN cross-account
  • D) Use AWS Config with auto-remediation to enable KMS encryption on non-compliant buckets every 24 hours
  • E) Deploy AWS Macie in the Security account to detect unencrypted S3 objects and alert

Correct: A and C

Why A: SCP with Deny unless SSE-KMS with specific key ARN prevents ANY S3 PutObject without encryption — enforced at the org level, cannot be overridden. This is a preventative control.

Why C: S3 default bucket encryption ensures objects are encrypted when no encryption is specified at upload. Combined with the SCP (A), it forms a complete defense-in-depth.

Why B is wrong: Deleting objects after upload is reactive — you've already stored unencrypted data momentarily. Regulatory requirements need preventative controls.

Why D is wrong: 24-hour auto-remediation means up to 24 hours of non-compliant state — unacceptable for regulation.

Why E is wrong: Macie detects PII — it doesn't detect or enforce encryption requirements.

Q152
Hard
Domain 2: Complex Networking

A company runs a multi-tenant SaaS platform. Each tenant's VPC uses the 10.x.0.0/16 CIDR range (all tenants use the same CIDR block). The company needs to route traffic from a shared services VPC (172.16.0.0/16) to each tenant VPC individually for monitoring purposes, without VPC peering CIDR conflicts. Which networking solution allows this?

  • A) VPC Peering between the shared services VPC and each tenant VPC
  • B) AWS Transit Gateway connecting all tenant VPCs
  • C) AWS PrivateLink — each tenant exposes a Network Load Balancer, and the shared services VPC accesses each tenant via Interface VPC Endpoints
  • D) NAT Gateway in each tenant VPC pointing to the shared services VPC

Correct: C

Why C: PrivateLink allows service access from one VPC to another regardless of overlapping CIDR blocks. Each tenant's NLB exposes a PrivateLink service. The shared services VPC connects via Interface Endpoints (private IPs from shared services CIDR). No route tables needed, no CIDR conflicts.

Why A is wrong: VPC Peering REQUIRES non-overlapping CIDRs. 40 tenant VPCs all using 10.x.0.0/16 cannot be peered with each other or with the shared VPC.

Why B is wrong: Transit Gateway also requires non-overlapping CIDRs between connected VPCs for routing. Overlapping CIDRs would create routing ambiguity.

Why D is wrong: NAT Gateway doesn't solve routing to specific tenant VPCs with overlapping CIDRs.

Q153
Hard
Domain 2: Databases

A gaming company's DynamoDB table handles 500,000 reads/second at peak. The game has a leaderboard feature that shows the top 100 players in real-time. The current implementation performs a DynamoDB Scan operation which is slow and expensive. How should the architect redesign this? (Select TWO)

  • A) Increase RCU provisioned capacity by 10x to handle more Scans
  • B) Create a Global Secondary Index (GSI) on the score attribute with a sort key for descending order, allowing an efficient Query for top-N players
  • C) Use DynamoDB Streams + Lambda to maintain a separate sorted leaderboard table updated on each score change, and cache the top 100 in ElastiCache Redis with a 5-second TTL
  • D) Switch to Amazon RDS Aurora for the leaderboard query since SQL ORDER BY handles this better
  • E) Add a DynamoDB DAX cluster to cache the Scan results

Correct: B and C

Why B: GSI on score allows an efficient Query with ScanIndexForward=false (descending) using a partition key like "LEADERBOARD" and score as sort key — O(log n) instead of O(n) table scan.

Why C: DynamoDB Streams trigger Lambda on writes → maintain a pre-sorted leaderboard table. ElastiCache Redis caches the top 100 at microsecond latency. This is the pattern for real-time leaderboards at scale.

Why A is wrong: More RCU for Scans still reads the ENTIRE table — linear cost growth, no performance improvement per query.

Why D is wrong: Migrating to Aurora to fix a DynamoDB query pattern is not the right approach. Fix the data model first.

Why E is wrong: DAX caches exact query results. If the Scan is cached, it's only fast for repeated identical scans — but the leaderboard changes frequently, so cached scan results would be stale.

Q154
Hard
Domain 3: Continuous Improvement

A company is deploying a new version of their microservice and wants to shift 10% of traffic to the new version initially, monitor error rates, and if error rate stays below 1%, gradually increase traffic to 100% over 2 hours. If error rate exceeds 1%, automatically roll back. Which deployment strategy and services implement this?

  • A) Blue/Green deployment using Route 53 weighted routing, with CloudWatch Alarms triggering Lambda to change weights
  • B) AWS CodeDeploy linear or canary deployment on ECS or Lambda, with CloudWatch Alarms configured as deployment rollback triggers
  • C) Application Load Balancer weighted target groups with CloudWatch Alarm → SNS → manual intervention
  • D) AWS Elastic Beanstalk rolling deployment with health check-based rollback

Why B: CodeDeploy on ECS/Lambda supports canary (10% → 100%) and linear deployment strategies with built-in CloudWatch Alarm integration. If the alarm fires, CodeDeploy automatically rolls back the deployment — no custom automation needed.

Why A is wrong: Route 53 + Lambda works but requires custom automation for the gradual traffic shift and rollback logic. More operational overhead than CodeDeploy's native capability.

Why C is wrong: ALB weighted TGs + SNS = manual intervention in rollback path. Not automated enough for this requirement.

Why D is wrong: Elastic Beanstalk rolling deploys sequentially to batches of instances — it's not a canary/weighted traffic shift strategy.

Q155
Hard
Domain 1: IAM & Cross-Account

A company's Data Science team (in Account A) needs to read from an S3 bucket (in Account B) and write results to another S3 bucket (in Account A). The Data Science EC2 instances use an IAM role. What is the CORRECT and MOST SECURE cross-account access approach?

  • A) Create IAM access keys in Account B and store them in the EC2 instance profile in Account A
  • B) In Account B, create an IAM role with S3 read permission, trust policy allowing Account A's EC2 role to assume it. In Account A's EC2 instance role, grant sts:AssumeRole permission targeting the Account B role. Update the Account B S3 bucket policy to allow the Account B role.
  • C) Enable S3 Cross-Region Replication from Account B to Account A so the data is available locally
  • D) Add the Account A EC2 instance role's ARN directly to the Account B S3 bucket policy

Correct: B

Why B: The standard cross-account pattern: (1) Account B role with trust policy permitting Account A's EC2 role. (2) Account A EC2 role has sts:AssumeRole permission. (3) Bucket policy grants the Account B role access. EC2 assumes the Account B role via STS, gets temporary credentials, reads S3. Most secure — no long-term credentials stored anywhere.

Why A is wrong: Long-term access keys are a security anti-pattern — they can be leaked, stolen, and don't auto-rotate.

Why C is wrong: CRR copies data but doesn't enable direct cross-account S3 API access. It would also duplicate data unnecessarily.

Why D is wrong: Adding Account A's EC2 role ARN to Account B's bucket policy CAN work for same-region same-account buckets, but for cross-account, the bucket policy alone doesn't grant access to principals from another account without the target account also having permission. The role assumption pattern (B) is more secure and explicit.

Professional Questions (Q241–300)

Highly complex multi-service architectures, enterprise-scale trade-offs, real-world migration challenges

Q241
Professional
Domain 1: Enterprise Complexity

A global bank is designing a multi-region AWS architecture for its trading platform. Requirements: (1) Writes in us-east-1 ONLY during normal operations; (2) Reads served from the nearest region; (3) Automatic regional failover with RPO < 5 seconds; (4) Cross-region data must be encrypted in transit using customer-managed keys; (5) Audit all data access globally. Which architecture satisfies ALL requirements? (Select THREE)

  • A) Aurora Global Database: primary writer in us-east-1, read-only replicas in eu-west-1 and ap-southeast-1. Global cluster replication <1 sec. On failover, promote a secondary to primary.
  • B) DynamoDB Global Tables with multi-active writes enabled in all regions
  • C) Route 53 Latency routing with health checks: direct reads to nearest region's Aurora endpoint; detect us-east-1 failure and failover writes to secondary region
  • D) AWS KMS with a multi-region CMK replicated to eu-west-1 and ap-southeast-1 for consistent encryption of Aurora storage and data in transit
  • E) CloudTrail enabled per-region with separate logging for each regional account

Correct: A, C, and D

Why A: Aurora Global Database provides <1 sec replication (satisfies RPO <5 sec). Primary writer in us-east-1. Read replicas in other regions for local reads. Manual or automated promote on failover.

Why C: Route 53 Latency routing serves reads from nearest region (Aurora read endpoints). Health checks detect us-east-1 failure for automatic write failover. TTL of 30s for quick DNS propagation.

Why D: KMS multi-region keys replicate the same key material to all regions — needed for consistent encryption/decryption of Aurora data across regions. Satisfies requirement 4.

Why B is wrong: DynamoDB Global Tables allows writes in ALL regions — requirement 1 says writes ONLY in us-east-1 during normal operations. Aurora Global is the right choice here for strict write locality.

Why E is wrong: Separate per-region CloudTrail doesn't satisfy "audit globally" — an Organization Trail with central S3 in a Log Archive account provides unified global audit.

Domain 4: Migration & Modernization

A company is running a legacy monolithic Java application on-premises with these characteristics: (1) 15 years old, 2 million lines of code; (2) PostgreSQL 9.6 database with 50 TB; (3) Deep filesystem dependency on NFS shares; (4) Uses 3rd-party COTS components that cannot be recompiled; (5) Business requires zero changes to vendor components; (6) Go-live target in 6 months. What migration strategy and services are MOST appropriate? (Select TWO)

  • A) Refactor to microservices using Lambda + DynamoDB (Refactor/Re-architect strategy)
  • B) Rehost (Lift-and-Shift) using AWS Application Migration Service (MGN) for the application servers, targeting EC2 instances with EFS for the NFS shares
  • C) Replatform the PostgreSQL database: use AWS DMS with CDC to migrate to Amazon Aurora PostgreSQL (same engine compatibility), with minimal downtime during cutover
  • D) Repurchase the COTS components with cloud-native SaaS equivalents to reduce dependency
  • E) Relocate the entire stack to AWS Outposts to avoid application changes

Correct: B and C

Why B: MGN performs lift-and-shift with zero application changes. EFS provides managed NFS that the application uses identically to on-prem NFS. COTS components run unchanged on EC2. 6-month timeline is achievable for Rehost.

Why C: Aurora PostgreSQL is PostgreSQL-compatible — minimal application changes for DB connection strings. DMS with CDC allows migration with minimal downtime (CDC keeps target in sync during migration, then brief cutover). 50 TB is large but manageable with DMS + SCT (same engine, so SCT minimal changes).

Why A is wrong: Refactoring 2M LOC to Lambda/DynamoDB in 6 months is unrealistic. The COTS components also cannot be recompiled, making microservices decomposition impossible within timeline.

Why D is wrong: "Business requires zero changes to vendor components" directly contradicts replacing them.

Why E is wrong: Outposts is for truly on-prem-requirement workloads. The company is migrating TO AWS, not keeping on-prem. Outposts would be expensive and doesn't achieve cloud benefits.

Domain 2: Complex Architecture

A company processes financial transactions using an event-driven architecture: (1) Orders arrive via API Gateway to Lambda; (2) Each order triggers 5 downstream services (inventory, payment, shipping, notification, fraud-check); (3) ALL 5 services must succeed for the order to be committed; (4) If any service fails, the ENTIRE order must be rolled back including compensating transactions; (5) Each step must be audited. Which architecture implements this pattern with LEAST custom code?

  • A) API Gateway → Lambda → SQS → 5 separate Lambda consumers → DynamoDB for state tracking
  • B) API Gateway → Lambda → AWS Step Functions Standard Workflow (SAGA pattern with compensating transactions), with each state invoking a service Lambda, rollback states for each service, and CloudTrail for audit
  • C) API Gateway → Lambda → EventBridge → 5 target Lambda functions → DynamoDB transactions
  • D) API Gateway → SNS → 5 SQS queues → Lambda consumers → manual state machine in DynamoDB

Correct: B

Why B: Step Functions Standard Workflow implements the SAGA pattern: each state is a service call. On failure, Step Functions executes compensating transaction states (rollback). Built-in state machine provides audit trail in execution history. Error handling, retry, and rollback logic all declarative in ASL — LEAST custom code. Step Functions integrations with Lambda, SNS, DynamoDB require no custom code for orchestration.

Why A is wrong: 5 parallel SQS consumers with DynamoDB state tracking requires building a custom distributed saga with complex state management — HIGH custom code.

Why C is wrong: EventBridge fan-out is fire-and-forget — it has no built-in rollback capability. Managing compensating transactions requires significant custom code.

Why D is wrong: SNS → SQS → Lambda fan-out with manual DynamoDB state machine requires building a complete custom saga orchestrator — maximum custom code.

Domain 3: Continuous Improvement — Security

A company's security audit found that EC2 instances in the production VPC can still reach the internet via a NAT Gateway. The security team wants: (1) Internet access for EC2 instances ONLY when an SSM Session Manager connection is active; (2) No SSH keys on any instance; (3) All sessions recorded for compliance; (4) Ability to revoke access for specific instances immediately; (5) Works across all 20 accounts in the organization. Which architecture satisfies ALL requirements?

  • A) Remove NAT Gateways. Enable SSM Agent on all EC2 instances. Create Interface VPC Endpoints for SSM services (ssm, ssmmessages, ec2messages). Enable SSM Session Manager with session logging to S3/CloudWatch. Apply SCP denying SSH ports.
  • B) Keep NAT Gateway but add a WAF rule blocking SSH traffic from the internet
  • C) Use AWS Config to detect instances with SSH enabled and auto-revoke security group rules
  • D) Deploy a bastion host in a public subnet with MFA-enabled login for all instance access

Correct: A

Why A: SSM Session Manager with VPC Endpoints eliminates internet access need. No SSH keys. Sessions recorded to S3/CloudWatch. Remove IAM ssm:StartSession permission to instantly revoke access. SCPs enforce no SSH ports org-wide. This is the AWS recommended zero-trust access pattern.

Why B is wrong: WAF doesn't block EC2-initiated outbound internet traffic. NAT Gateway still exposes instances.

Why C is wrong: Config auto-remediation is reactive — there's a window of exposure. SSM with VPC Endpoints is preventative.

Why D is wrong: Bastion hosts still require SSH keys and internet exposure — contrary to requirements 1 and 2.

A media company processes 10 TB of video data daily. They need: real-time transcoding triggered on upload, metadata indexing, searchable content catalog, and a recommendation engine. Costs must stay under $50k/month. Which architecture achieves this?

  • A) S3 Upload → S3 Event Notification → SQS → Lambda (metadata extraction) → DynamoDB (catalog) + OpenSearch (search). Separate pipeline: S3 → AWS Elemental MediaConvert for transcoding → S3 output. SageMaker for recommendations trained on DynamoDB Streams.

  • D) EMR cluster running 24/7 for all processing with Spark
