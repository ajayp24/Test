1. VPC Architecture

Amazon VPC (Virtual Private Cloud) is a logically isolated section of the AWS cloud where you can launch AWS resources in a virtual network you define. It's the foundational networking primitive for almost everything in AWS.

┌─────────────────────────────────────────────────────────────────────┐ │ VPC: 10.0.0.0/16 │ │ │ │ ┌─────────────────────┐ ┌────────────────────┐ │ │ │ Public Subnet │ │ Private Subnet │ │ │ │ 10.0.1.0/24 (AZ-a) │ │ 10.0.2.0/24 (AZ-a) │ │ │ │ │ │ │ │ │ │ ┌─────────────────┐ │ │ ┌────────────────┐ │ │ │ │ │ EC2 Web Server │ │ │ │ EC2 App Server│ │ │ │ │ │ (Public IP) │ │ │ │ (Private IP) │ │ │ │ │ └────────┬────────┘ │ │ └───────┬────────┘ │ │ │ └──────────┼──────────┘ └─────────┼──────────┘ │ │ │ │ │ │ ┌──────────▼──────────────────────────▼──────────┐ │ │ │ NAT Gateway (in public subnet) │ │ │ └──────────────────────────┬─────────────────────┘ │ │ │ │ │ ┌──────────────────────────▼───────────────────────┐ │ │ │ Internet Gateway (IGW) │ │ │ └──────────────────────────┬───────────────────────┘ │ │ │ │ │ INTERNET │ └─────────────────────────────────────────────────────────────────────┘

VPC Key Facts

  • Default VPC exists in every region per account (CIDR: 172.31.0.0/16)
  • Max 5 VPCs per Region by default (soft limit, can request increase)
  • Max CIDR: /16 (65,536 IPs); Min CIDR: /28 (16 IPs)
  • Can have up to 5 CIDR blocks per VPC
  • VPCs span all AZs in a Region — subnets are AZ-specific
  • Each subnet loses 5 IPs: network, router, DNS, future, broadcast

Exam Trap: NACLs are stateless. If you allow port 80 inbound, you must also allow the ephemeral port range (1024–65535) outbound for response traffic. Security groups are stateful — response traffic is automatically permitted.

5. VPC Peering

  • Direct, private connection between two VPCs (same or different account/region)
  • Not transitive: A peered to B, B peered to C does NOT allow A to reach C
  • CIDRs must NOT overlap
  • No IGW required — traffic flows over AWS backbone
  • Max 125 peering connections per VPC
  • Lower cost than Transit Gateway for simple 2-VPC connections

6. AWS PrivateLink

PrivateLink allows exposing services from one VPC to other VPCs privately, without peering, without routing through the internet, and without exposing the producer VPC's IP range.

SERVICE PROVIDER VPC SERVICE CONSUMER VPC ┌───────────────────────┐ ┌──────────────────────────┐ │ NLB ──► EC2 Service │ │ EC2 App │ │ ↕ │◄────────────│ ↕ │ │ Endpoint Service │ PrivateLink│ Interface VPC Endpoint │ │powered by PrivateLink)│ │ ENI in consumer subnet) │ └───────────────────────┘ └──────────────────────────┘ Traffic: Consumer ENI → PrivateLink → Provider NLB → Service Never leaves AWS network. No VPC peering needed. CIDRs CAN overlap (unlike peering).

8. Route 53 — DNS & Routing Policies

Amazon Route 53 is a highly available, scalable DNS web service. It also serves as a domain registrar and health checking service.

Route 53 Routing Policies

Routing PolicyHow It WorksUse Case
SimpleSingle DNS record → single resource (or random from multiple values)Single server, no health check
WeightedDistribute traffic by percentage (10% → v2, 90% → v1)Blue/green deployments, A/B testing
LatencyRoute to region with lowest latency from user's locationMulti-region apps, global users
FailoverPrimary resource with health check; fail to secondary if unhealthyActive-passive DR, hot standby
GeolocationRoute based on user's geographic location (continent, country)Content localization, regulatory compliance
GeoproximityRoute based on proximity + optional bias to shift trafficFine-grained geographic routing
Multi-Value AnswerReturn up to 8 healthy records; client choosesSimple load distribution with health checks
IP-basedRoute based on CIDR of the client's IPISP routing, specific client networks
Exam Trap: Latency routing does NOT route based on geography — it routes based on which endpoint has the lowest NETWORK LATENCY from the user's perspective. A user in Australia might be routed to us-west-2 if DX connection is faster than the Sydney region link.

Route 53 Health Checks

  • Endpoint health checks: HTTP, HTTPS, TCP checks from 18+ global health checker locations
  • Calculated health checks: Combine multiple health checks with AND/OR logic
  • CloudWatch alarm health checks: Fail if a CloudWatch alarm triggers
  • Health checks can be applied to Failover, Weighted, Latency, Geolocation routing policies
  • Can monitor resources in private VPCs via VPC-associated health checks

Private Hosted Zones

A Private Hosted Zone resolves DNS names within a VPC without public exposure. You must associate the PHZ with each VPC that needs to resolve those names.

# Create Private Hosted Zone
aws route53 create-hosted-zone \
  --name internal.mycompany.com \
  --caller-reference "$(date)" \
  --hosted-zone-config Comment="Internal DNS",PrivateZone=true \
  --vpc VPCRegion=us-east-1,VPCId=vpc-xxxxxxxx

# Associate additional VPC with PHZ
aws route53 associate-vpc-with-hosted-zone \
  --hosted-zone-id Z1234567890ABC \
  --vpc VPCRegion=us-east-1,VPCId=vpc-yyyyyyyy

9. CloudFront

Amazon CloudFront is a CDN (Content Delivery Network) that delivers content from Edge Locations closest to users for low-latency delivery.

USER REQUEST FLOW WITH CLOUDFRONT User (Tokyo) ──► CloudFront Edge (Tokyo) ──► Cache HIT? ──► Return content │ └──► Cache MISS │ └──► Regional Edge Cache │ └──► Origin (us-east-1) (S3, ALB, EC2, Custom)

CloudFront Origins

  • S3: Use Origin Access Control (OAC) to restrict S3 access only to CloudFront
  • ALB/EC2: Dynamic content — CloudFront proxies requests to your custom origin
  • API Gateway: Caching for API responses
  • MediaStore/MediaPackage: Video streaming

10. Global Accelerator

AWS Global Accelerator routes traffic over the AWS global network backbone instead of the public internet, using Anycast static IP addresses. Traffic enters the AWS network at the nearest PoP (Point of Presence) and is routed internally to the endpoint (ALB, NLB, EC2, Elastic IP).

  • Provides 2 static Anycast IP addresses that do not change
  • Automatic failover to healthy endpoints in seconds
  • Health checks built-in — removes unhealthy endpoints automatically
  • Works with TCP and UDP protocols (unlike CloudFront, which is HTTP only)
  • Traffic weighted routing between endpoints

Terraform — Transit Gateway

# Create Transit Gateway (in Network Account)
resource "aws_ec2_transit_gateway" "main" {
  description                     = "Enterprise Transit Gateway"
  amazon_side_asn                 = 64512
  auto_accept_shared_attachments  = "enable"
  default_route_table_association = "disable"
  default_route_table_propagation = "disable"
  dns_support                     = "enable"
  vpn_ecmp_support                = "enable"

  tags = { Name = "enterprise-tgw" }
}

# Share TGW via RAM (Resource Access Manager)
resource "aws_ram_resource_share" "tgw_share" {
  name                      = "tgw-share"
  allow_external_principals = false
}

resource "aws_ram_resource_association" "tgw" {
  resource_arn       = aws_ec2_transit_gateway.main.arn
  resource_share_arn = aws_ram_resource_share.tgw_share.arn
}

# Attach Prod VPC to TGW
resource "aws_ec2_transit_gateway_vpc_attachment" "prod" {
  subnet_ids         = var.prod_private_subnet_ids
  transit_gateway_id = aws_ec2_transit_gateway.main.id
  vpc_id             = var.prod_vpc_id

  tags = { Name = "prod-vpc-attachment" }
}

12. Exam Tips & Cheat Sheet

SAP-C02 Networking — Critical Points

  • VPC Peering is NOT transitive. Need full mesh or use Transit Gateway.
  • Gateway Endpoints (S3, DynamoDB) = free, no ENI. Interface Endpoints = $0.01/hr/AZ, creates ENI.
  • PrivateLink vs Peering: PrivateLink allows CIDR overlap; peering does not. PrivateLink = one-way service exposure.
  • NACLs are stateless — always allow ephemeral ports on outbound for inbound rules.
  • Direct Connect: Not encrypted by default. Add IPsec VPN over DX for encryption.
  • Route 53 Latency: Routes based on latency, not geography.
  • Route 53 Failover: Requires health checks. Use for active-passive DR.
  • CloudFront: HTTP/HTTPS only. Global Accelerator: TCP/UDP protocols.
  • NAT Gateway: Managed, AZ-resilient (deploy one per AZ). NAT Instance: Self-managed, cheaper but complex.
  • Transit Gateway: Enables transitive routing. Supports 5,000 attachments. Cross-account via RAM.
  • Egress-Only IGW: IPv6 equivalent of NAT Gateway — allows outbound IPv6 from private subnets.
Connectivity Comparison
  • VPN: encrypted, fast setup, variable latency
  • DX: private, consistent latency, high bandwidth
  • Peering: no transitive, no overlap, 125 limit
  • TGW: transitive, 5000 VPCs, cross-account/region
  • PrivateLink: 1-way, CIDR overlap OK
Route 53 Routing
  • Simple → single resource
  • Weighted → A/B, canary
  • Latency → lowest RTT
  • Failover → active-passive DR
  • Geolocation → regulatory/content
  • Multi-Value → 8 healthy records
VPC Endpoints
  • Gateway: S3, DynamoDB only, FREE
  • Interface: All other services, $0.01/hr
  • Both: keep traffic off internet
  • Interface: creates ENI in your subnet
CloudFront vs GA
  • CloudFront: HTTP/HTTPS, caching
  • Global Accelerator: TCP/UDP, no cache
  • Both: AWS global backbone
  • S3 Transfer Accel: faster uploads only
