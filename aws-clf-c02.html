Chapter 1

Cloud Concepts & Value Proposition

This domain covers 24% of the exam. You must understand what cloud computing is, the different deployment models, the six advantages of cloud, and the AWS Well-Architected Framework. These are foundational concepts that appear throughout every other domain.

☁

What Is Cloud Computing?

On-demand delivery of IT resources over the internet with pay-as-you-go pricing
📚 Definition

Cloud computing is the on-demand delivery of compute power, database storage, applications, and other IT resources through a cloud services platform via the internet with pay-as-you-go pricing. Instead of buying, owning, and maintaining physical data centers and servers, you can access technology services on an as-needed basis from a cloud provider like AWS.

💡 Real-World Analogy

Think of cloud computing like electricity from a power company. You don't build your own power plant — you plug into the grid and pay only for what you use. Similarly, with cloud computing, you don't build your own data center — you use AWS's infrastructure and pay only for the resources you consume.

📚 Five Characteristics of Cloud Computing
  • On-demand self-service: Provision resources (servers, storage, databases) without human interaction with the provider. Use the console, CLI, or API.
  • Broad network access: Resources are available over the network (internet) and accessed through standard mechanisms (browsers, apps, APIs).
  • Multi-tenancy & resource pooling: Multiple customers share the same physical infrastructure, with security and privacy. You don't know (or care) where your data physically sits.
  • Rapid elasticity & scalability: Automatically acquire and release resources based on demand. Scale up during Black Friday, scale down at night.
  • Measured service: Usage is metered. You pay exactly for what you use (per hour, per GB, per request).

Six Advantages of Cloud Computing

AWS's official reasons why companies should move to the cloud
Must Memorize — These Appear on Every Exam
  1. Trade upfront expense for variable expense: No more buying servers upfront (CapEx). Pay only for what you consume (OpEx). Reduces financial risk.
  2. Benefit from massive economies of scale: AWS aggregates usage from hundreds of thousands of customers, achieving higher economies of scale than you could alone. This translates to lower prices.
  3. Stop guessing capacity: No more over-provisioning (waste) or under-provisioning (outages). Scale up or down in minutes based on actual demand.
  4. Increase speed and agility: New IT resources are a click away. Reduce time to deploy from weeks/months to minutes. Experiment more, fail fast, innovate faster.
  5. Stop spending money running and maintaining data centers: Focus on your business, not on racking servers, running cables, and managing power/cooling. Let AWS handle undifferentiated heavy lifting.
  6. Go global in minutes: Deploy your application in multiple AWS Regions around the world with a few clicks. Lower latency for global users.

🛠

Cloud Design Principles

Key architectural principles for building on AWS
  • Design for failure: Everything fails eventually. Design systems that can tolerate failure. Use multiple AZs, auto-scaling, and health checks.
  • Decouple your components: Loose coupling means components don't depend directly on each other. Use SQS, SNS, and load balancers to decouple.
  • Implement elasticity: Scale out (add more instances) rather than scale up (bigger instance). Use Auto Scaling Groups.
  • Think parallel: Instead of one big server, use many small ones working in parallel for better performance and fault tolerance.
  • Keep dynamic data close to compute, static data close to users: Use caching (ElastiCache, CloudFront) for frequently accessed data.
  • Don't fear constraints — leverage managed services: Use RDS instead of installing MySQL on EC2. Use DynamoDB instead of running MongoDB. Let AWS handle the undifferentiated heavy lifting.

How to Choose a Region

Four factors to consider when selecting an AWS region
Four Factors (Common Exam Question)
  1. Compliance & Data Governance: Data may need to stay in a specific country/region due to laws and regulations (e.g., GDPR requires EU data to stay in Europe). This is always the #1 factor.
  2. Proximity to Users: Choose a region close to your users for lower latency. A user in Tokyo will have better performance from ap-northeast-1 than from us-east-1.
  3. Available Services: Not all AWS services are available in every region. New services typically launch in us-east-1 first.
  4. Pricing: Pricing varies between regions. us-east-1 is typically the cheapest. Compare costs using the AWS Pricing Calculator.

Exam Trap

IAM is global — users and roles are not tied to a region. S3 bucket names are globally unique but buckets are regional (data stays in the chosen region). The exam loves testing this distinction.

Compute Services

Compute is at the heart of cloud technology. You must know EC2 instance types, pricing models, Lambda serverless, containers (ECS/Fargate/EKS), Elastic Beanstalk, and Lightsail. Especially important: EC2 pricing models are tested heavily.

🖥

Amazon EC2

Virtual servers in the cloud
📚 Definition

Amazon Elastic Compute Cloud (EC2) provides resizable virtual servers (called instances) in the cloud. You choose the operating system, instance type (CPU, memory, storage, network), and configure security. You have full control of the server, just like a physical machine.

💡 Real-World Analogy

EC2 is like renting a computer. You choose the size (small laptop vs powerful workstation), you install what you want, and you pay by the hour. When you're done, you return it and stop paying.

⚠ Exam Traps
Trap 1: Spot Instances Can Be Terminated

Spot Instances are NOT suitable for critical applications, databases, or anything that can't handle interruption. If the question says "must run continuously" or "cannot tolerate interruption," Spot is wrong.

Trap 2: Reserved Instances vs Savings Plans

Reserved Instances are tied to a specific instance type and region. Savings Plans are more flexible — you commit to a dollar amount per hour, and AWS applies the discount across instance types, sizes, OS, and even Fargate/Lambda. If the question mentions "flexibility," choose Savings Plans.

Trap 3: Dedicated Hosts vs Dedicated Instances

Dedicated Hosts = you control the physical server (needed for bring-your-own-license). Dedicated Instances = hardware isolation but no server control. The exam tests the difference: "bring your own license" = Dedicated Host.

🔬 Example Scenario
A company runs a web application that has steady, predictable traffic during business hours and needs to run 24/7 for the next 3 years. Which pricing model provides the most cost savings?
Answer: Reserved Instances (3-year term with All Upfront payment)
Steady, predictable, long-term workloads are the perfect use case for Reserved Instances. A 3-year All Upfront commitment provides the maximum discount (up to 72%). Savings Plans would also work but RIs with specific commitment provide the highest savings for known, stable workloads.

AWS Lambda

Run code without thinking about servers
📚 Definition

AWS Lambda is a serverless compute service. You upload your code, and Lambda runs it in response to events (like an S3 upload, API call, or database change). No servers to provision, patch, or manage. You pay only for the compute time consumed — billed per millisecond.

💡 Real-World Analogy

Lambda is like a vending machine. You put in a request (insert coin, press button), it does one specific thing (dispenses a drink), and shuts off. You don't maintain the machine, you just use it. Compare to EC2 which is like running your own restaurant — you manage everything.

  • Timeout: Maximum 15 minutes per invocation.
  • Pricing: Pay per request (first 1 million free/month) + per GB-second of compute time.
  • Scaling: Automatic. Can scale to thousands of concurrent executions.
  • Languages: Python, Node.js, Java, C#, Go, Ruby, custom runtimes.
  • Triggers: S3, API Gateway, DynamoDB, SQS, SNS, EventBridge, CloudWatch Events, and more.

AWS Elastic Beanstalk

Deploy and manage applications without worrying about infrastructure
📚 Definition

A Platform as a Service (PaaS). Upload your code and Beanstalk automatically handles deployment, capacity provisioning, load balancing, auto-scaling, and health monitoring. You still have full control of the underlying resources (EC2, ALB, ASG, RDS) if you need it.

  • Free to use — you only pay for the underlying AWS resources it creates.
  • Supports: Java, .NET, Node.js, PHP, Python, Ruby, Go, Docker.
  • Great for developers who want to deploy quickly without learning infrastructure.
💡 Analogy

Beanstalk is like a food truck service that gives you a ready-to-go truck with kitchen, fuel, and parking spot. You just bring the food (your code) and start cooking (running your app). You can still open the hood and modify the engine if needed.

💡

Amazon Lightsail

Simple cloud servers for beginners
  • Simple virtual servers with fixed, predictable monthly pricing.
  • Includes compute, storage, DNS, static IP, and data transfer in one bundle.
  • For people with little to no cloud experience. Simpler than EC2.
  • Good for simple websites, small apps, WordPress, development/test environments.
  • Limited customization compared to EC2.

Storage Services

S3 is the most important storage service on the exam. Know S3 storage classes, use cases, and the difference between S3 (object), EBS (block), and EFS (file) storage.

📦

Amazon S3 (Simple Storage Service)

Object storage with unlimited scalability
📚 Definition

Amazon S3 is an object storage service that stores data as objects within buckets. Each object has a key (name), the data itself (up to 5 TB), and metadata. S3 provides 99.999999999% (11 9's) durability and is designed for virtually unlimited storage.

💡 Real-World Analogy

S3 is like an infinite filing cabinet in the cloud. Each drawer is a bucket, each file is an object, and the label on the file is the key. You can store anything — documents, images, videos, backups — and find it instantly by its key.

  • Buckets: Containers for objects. Bucket names must be globally unique across all AWS accounts.
  • Objects: Files stored in buckets. Max size 5 TB. Objects have keys (full path including "folder" prefixes).
  • Use cases: Static website hosting, backups, data lakes, media hosting, software delivery, log storage, disaster recovery.
  • Access control: Bucket policies (JSON), IAM policies, ACLs (legacy), Block Public Access settings.
  • Versioning: Keep multiple versions of an object. Protects against accidental deletion.
  • Replication: Cross-Region Replication (CRR) for disaster recovery and compliance. Same-Region Replication (SRR) for log aggregation.

Amazon EBS (Elastic Block Store)

Persistent block storage for EC2 instances
  • Block storage that attaches to a single EC2 instance (like a virtual hard drive).
  • Data persists independently of the instance lifecycle (survives instance stop/start).
  • Bound to a specific Availability Zone. To move, take a snapshot and restore in another AZ.
  • EBS Snapshots: Point-in-time backups stored in S3. Can be copied across regions for disaster recovery.
  • Volume types: gp3/gp2 (general purpose SSD), io2/io1 (high-performance SSD), st1 (throughput HDD), sc1 (cold HDD).
💡 Analogy

EBS is like an external hard drive you plug into your computer. You can unplug it and keep the data, but you can only plug it into one computer at a time (mostly), and it has to be in the same room (AZ).

📁

Amazon EFS (Elastic File System)

Managed file storage that can be shared across multiple instances
  • Network file system (NFS) that can be mounted on many EC2 instances simultaneously across multiple AZs.
  • Automatically grows and shrinks as you add/remove files. No need to provision size.
  • Linux only. Does not work with Windows (use FSx for Windows).
  • More expensive than EBS but provides shared access and auto-scaling.
  • Use cases: content management, web serving, shared home directories, big data analytics.

Database Services

Know when to use relational (RDS/Aurora) vs NoSQL (DynamoDB) databases, and be familiar with purpose-built databases for specific workloads.

🗃

Amazon RDS & Aurora

Managed relational databases
📚 Amazon RDS
  • Managed relational database service. AWS handles patching, backups, scaling, and high availability.
  • Engines: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, and Amazon Aurora.
  • Multi-AZ: Automatic failover to a standby replica in another AZ for high availability.
  • Read Replicas: Scale read-heavy workloads. Up to 15 replicas for Aurora, 5 for others.
  • Automated backups: Point-in-time recovery within a retention period (up to 35 days).
  • You cannot SSH into an RDS instance — it's fully managed.
📚 Amazon Aurora
  • AWS's own cloud-native relational database. Compatible with MySQL and PostgreSQL.
  • 5x faster than standard MySQL, 3x faster than standard PostgreSQL.
  • Auto-scales storage from 10 GB to 128 TB. Replicates 6 copies of data across 3 AZs.
  • Aurora Serverless: Auto-scales compute capacity based on demand. Pay per second. Great for infrequent or unpredictable workloads.
  • Costs ~20% more than RDS but provides better performance and availability.
Exam Tip

If the question says "AWS's own cloud-optimized relational database" or "MySQL/PostgreSQL compatible with better performance," the answer is Aurora.

⚡

Amazon DynamoDB

Fully managed, serverless NoSQL database
  • Key-value and document NoSQL database. Serverless — no servers to manage.
  • Single-digit millisecond performance at any scale.
  • Automatically scales. Supports millions of requests per second.
  • Global Tables: Multi-region, active-active replication for global applications.
  • DAX (DynamoDB Accelerator): In-memory cache for microsecond read latency.
  • Stores data in tables with items (rows) and attributes (columns). Flexible schema.
RDS vs DynamoDB

"Structured data, relationships, joins, SQL queries" → RDS/Aurora (relational).
"Flexible schema, key-value, high scale, serverless, millisecond latency" → DynamoDB (NoSQL).
"Cannot handle the schema changes" → DynamoDB (schema-less).

🔒

Amazon VPC (Virtual Private Cloud)

Your private, isolated network in the AWS cloud
📚 Key Components
💡 Analogy

A VPC is like your own private office building. The building has rooms (subnets), security guards at each room door (security groups), and a guest list at the building entrance (NACLs). Some rooms face the street (public subnets), and some are hidden in the back (private subnets).

ComponentWhat It Does
SubnetsSegments of your VPC. Public subnets have a route to the internet (via Internet Gateway). Private subnets do not.
Internet Gateway (IGW)Connects your VPC to the internet. Required for public subnets.
NAT GatewayAllows instances in private subnets to access the internet (for updates, patches) while remaining private. One-way: outbound only.
Security GroupsVirtual firewall at the instance level. Stateful (if you allow inbound traffic, outbound response is automatically allowed). Only allow rules, no deny rules. Default: deny all inbound, allow all outbound.
Network ACLs (NACLs)Virtual firewall at the subnet level. Stateless (must explicitly allow both inbound and outbound). Supports both allow AND deny rules. Default: allow all traffic.
VPC EndpointsPrivate connection from your VPC to AWS services (S3, DynamoDB) without going through the internet.
VPC PeeringConnect two VPCs privately. Non-transitive (A ↔ B, B ↔ C does NOT mean A ↔ C).
VPC Flow LogsCapture network traffic information in your VPC. Useful for troubleshooting and security monitoring.

Amazon Route 53

Scalable DNS and domain name registration
  • DNS service that translates domain names (www.example.com) to IP addresses.
  • Also provides domain name registration (buy domain names directly).
  • Health checks: Monitor the health of resources and route traffic away from unhealthy ones.
  • Routing policies: Simple, Weighted (% distribution), Latency-based (closest region), Failover (active-passive), Geolocation (based on user location), Multi-value.
  • 100% SLA availability — the only AWS service with this guarantee.
  • Global service (not region-specific).
🚀

Amazon CloudFront

Global Content Delivery Network (CDN)
  • Caches content at 450+ edge locations worldwide for low-latency delivery.
  • Origins: S3 buckets, ALB, EC2, custom HTTP server.
  • DDoS protection built-in (integrated with AWS Shield).
  • Can restrict access using signed URLs and signed cookies.
  • Supports HTTPS with free SSL/TLS certificates (via ACM).
  • Global service.
CloudFront vs S3 Cross-Region Replication

CloudFront: Static content distributed globally via CDN edge caches. Content is cached with a TTL. Great for static websites, media, and APIs.
S3 CRR: Full replication of objects to another region bucket. Near real-time. Great for compliance, lower-latency access to dynamic content.

📚 Core Components
ComponentWhat It IsKey Fact

⚠ Exam Traps
Principle of Least Privilege

Grant only the permissions needed to perform a task. Don't give admin access when read-only is sufficient. This principle is tested repeatedly on the exam.

Root User Best Practices

1. Enable MFA on root immediately. 2. Create an IAM admin user for daily tasks. 3. Never share root credentials. 4. Never create access keys for root. The exam will ask: "What should you do FIRST after creating an AWS account?" → Enable MFA on root and create an IAM admin user.

MFA & Access Keys

Extra layers of security for your AWS account
  • MFA (Multi-Factor Authentication): Adds a second factor (something you know + something you have). Options: Virtual MFA device (Google Authenticator, Authy), Hardware MFA key (YubiKey), Hardware key fob.
  • Access Keys: Used for programmatic access (CLI, SDK). Consist of Access Key ID + Secret Access Key. Never share or embed in code. Use IAM roles instead whenever possible.
  • AWS CLI: Command-line tool to interact with AWS services. Requires access keys or role-based credentials.
  • AWS SDK: Programming libraries to interact with AWS from your code (Python boto3, JS SDK, Java SDK, etc.).
  • AWS CloudShell: Browser-based shell in the AWS Console. Pre-authenticated, no setup needed.

Encryption & KMS

Protect data at rest and in transit
  • Encryption at rest: Data is encrypted when stored (on disk). Services: S3 (SSE-S3, SSE-KMS, SSE-C), EBS encryption, RDS encryption, Glacier encryption.
  • Encryption in transit: Data is encrypted while moving (over the network). Uses TLS/SSL (HTTPS). Services: All AWS APIs use HTTPS by default.
  • AWS KMS (Key Management Service): Create and manage encryption keys. AWS manages the keys for you. Integrated with most AWS services. Customer-managed keys give you full control (rotation, access policies).
  • AWS CloudHSM: Hardware Security Module. You manage your own encryption keys on dedicated hardware. FIPS 140-2 Level 3 compliance.
  • AWS Secrets Manager: Store, rotate, and manage secrets (database passwords, API keys). Automatic rotation.
  • AWS Certificate Manager (ACM): Free public SSL/TLS certificates for your websites and applications. Auto-renewed.
KMS vs CloudHSM

KMS: AWS manages the encryption hardware. Multi-tenant. Easier to use. Sufficient for most workloads.
CloudHSM: You manage the keys on dedicated hardware. Single-tenant. Required for regulatory compliance that mandates customer-controlled HSM.

Amazon CloudWatch

Monitor resources and applications in real time
  • Metrics: Collect and track metrics from AWS services (EC2 CPU, ELB latency, Lambda duration, etc.).
  • Alarms: Set thresholds on metrics and trigger actions (SNS notification, Auto Scaling, EC2 stop/terminate).
  • Logs: Collect, monitor, and analyze log files from EC2, Lambda, CloudTrail, etc.
  • Dashboards: Create custom visualizations of metrics across services and regions.
  • Events / EventBridge: React to changes in your AWS environment in real time (e.g., trigger Lambda when EC2 state changes).
💡 Analogy

CloudWatch is like the dashboard in your car. It shows speed (CPU), fuel level (memory), engine temperature (errors), and alerts you when something needs attention (alarms).

👁

AWS CloudTrail

Track every API call made in your AWS account
  • Records every API call: who, what, when, from where. Console actions, CLI commands, SDK calls.
  • Enabled by default for 90 days of event history (free).
  • Create a Trail to store events long-term in S3 or CloudWatch Logs.
  • Use for: security analysis, compliance auditing, troubleshooting, incident investigation.
  • CloudTrail Insights: Detect unusual API activity patterns automatically.
CloudWatch vs CloudTrail vs Config

CloudWatch: "How is my resource performing?" (metrics, alarms, logs).
CloudTrail: "Who made this change?" (API call history, audit).
Config: "Is my resource configured correctly?" (compliance, configuration history).

AWS Pricing Models

Three fundamental pricing principles
Three Pricing Fundamentals
  1. Pay for compute time: Only when instances are running or functions are executing.
  2. Pay for data stored: Per GB stored in S3, EBS, RDS, etc.
  3. Pay for data transferred OUT: Data going out of AWS to the internet costs money. Data coming IN is free. Data transfer between services in the same region is often free or cheaper.
Key Pricing Facts

Inbound data transfer is always free.
Same-AZ data transfer between EC2 and RDS/ElastiCache using private IP: free.
Cross-AZ data transfer: small charge.
Cross-region data transfer: higher charge.
Internet outbound: charged per GB.

Exam Strategies & Quick Reference

🔬

Real CLF-C02 Scenario Walkthroughs

Practice with exam-style questions
Scenario 1: A company wants to run a web application that can handle traffic spikes during product launches. They want to pay only for the resources they use and minimize operational overhead. Which compute service should they use?
Answer: AWS Lambda (if short requests) or EC2 with Auto Scaling Group + ALB
If the application is composed of short, event-driven functions, Lambda provides automatic scaling and pay-per-use pricing with zero server management. If it's a traditional web app needing persistent servers, EC2 with an Auto Scaling Group automatically adds/removes instances during traffic spikes, and ALB distributes traffic across them.
Scenario 2: A healthcare company must store patient records and ensure the data never leaves the European Union due to GDPR. Which AWS feature enables this?
Answer: Choose an AWS Region in the EU (e.g., eu-west-1 Ireland, eu-central-1 Frankfurt)
AWS Regions are isolated from each other. Data stored in an EU region stays in that region unless you explicitly replicate it elsewhere. The company should select an EU region for all their services. This is the #1 factor for choosing a region: compliance and data residency requirements.
Scenario 3: A company's Security team wants to know who deleted an S3 bucket last Tuesday. Which AWS service should they check?
Answer: AWS CloudTrail
CloudTrail records every API call made in the account, including who made it, when, and from where. The DeleteBucket API call would be logged with the IAM identity, timestamp, source IP, and other details. This is the go-to service for "who did what" questions.
Scenario 4: A company runs a steady-state database server on EC2 that needs to run 24/7 for the next 3 years. What is the most cost-effective purchasing option?
Answer: Reserved Instance (3-year, All Upfront)
Steady, predictable, long-term = Reserved Instance. The 3-year All Upfront option provides the maximum discount (up to 72% off On-Demand). Spot Instances are wrong because the database cannot tolerate interruption. On-Demand is the most expensive option for 24/7 usage.
Scenario 5: Who is responsible for patching the operating system on an Amazon RDS database instance?
Answer: AWS (Shared Responsibility Model)
RDS is a managed service. AWS manages the underlying infrastructure including OS patching, database engine patching, and hardware maintenance. The customer is responsible for configuring security groups, managing database users, and encrypting data. Compare this with running MySQL on EC2, where the customer would be responsible for OS and database patching.

Top 15 CLF-C02 Exam Traps

The most commonly missed concepts
  1. Shared Responsibility: AWS patches RDS; YOU patch EC2 OS. Managed service = AWS handles more.
  2. Security Groups are stateful, NACLs are stateless. SGs allow only, NACLs allow AND deny.
  3. S3 buckets are regional (data stays in the region), but bucket names are globally unique.
  4. IAM is global — users and roles work across all regions.
  5. Spot Instances can be interrupted — never use for critical, uninterruptible workloads.
  6. Dedicated Host ≠ Dedicated Instance. Host = you control the physical server (BYOL). Instance = just hardware isolation.
  7. Direct Connect is NOT encrypted. VPN is encrypted. For encrypted Direct Connect, add a VPN on top.
  8. Data transfer IN to AWS is free. You pay for data going OUT.
  9. Trusted Advisor full checks require Business+ support. Basic/Developer only get 7 core checks.
  10. TAM (Technical Account Manager) requires Enterprise support. Enterprise On-Ramp gets a pool of TAMs.
  11. CloudTrail = who did what (audit). CloudWatch = how is it performing (monitoring). Config = is it configured correctly (compliance).
  12. EBS is single-AZ. EFS is multi-AZ. To move EBS across AZs, use snapshots.
  13. Lambda max timeout is 15 minutes. For longer tasks, use EC2, ECS, or Batch.
  14. AWS Artifact is for compliance documents (SOC reports, certifications), NOT for software artifacts.
  15. VPC Peering is non-transitive. A↔B and B↔C does NOT mean A↔C. You need a direct peering between A and C.
